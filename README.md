# 🧬 Diabetes RAG LLM

A Retrieval-Augmented Generation (RAG) system that answers questions about diabetes research using **5,000+ PubMed abstracts published 2010–2026**. It combines semantic search (FAISS + sentence-transformers) with a locally running LLM (Llama 3 via Ollama), and shows every answer alongside the papers it came from: title, authors, journal, year and a link to PubMed.

Everything runs locally: no API keys are needed except a free NCBI email for downloading abstracts.

> ⚕️ **Research tool, not medical advice.** Answers are generated by an AI from PubMed abstracts and may be incomplete or wrong.

---

## 📌 Overview

1. **Fetch:** a year-balanced set of diabetes abstracts is downloaded from PubMed (NCBI E-utilities), with title, journal, year, authors and study type (RCT, meta-analysis, review, ...)
2. **Preprocess:** abstracts are split into overlapping chunks; every chunk carries its paper's metadata
3. **Embed:** chunks are encoded with `all-MiniLM-L6-v2` into a FAISS index (cosine similarity)
4. **Retrieve:** the most similar chunks are found for each question; anything below a calibrated relevance threshold is dropped, so off-topic questions return nothing instead of weak matches
5. **Generate:** Llama 3 (via Ollama) answers **only from the retrieved excerpts**, citing PMIDs, and says so when the excerpts don't answer the question
6. **Interface:** a Streamlit web app and a terminal CLI show the answer with source cards and PubMed links

Design choices are recorded in [`docs/DECISIONS.md`](docs/DECISIONS.md), and known weaknesses in [`docs/OBSERVATIONS.md`](docs/OBSERVATIONS.md).

## 📚 The knowledge base

A single relevance-sorted PubMed search returns mostly the newest papers (an earlier version of this project was 99% from one year), so the corpus is fetched **year by year**: the 300 most relevant papers for each year from 2010 to 2026.

| | |
|---|---|
| Query | `"diabetes mellitus"[MeSH Major Topic] AND hasabstract[text] AND english[lang]` |
| Abstracts | 5,089 fetched, 5,080 used (stubs under 200 characters dropped) |
| Coverage | every year 2010–2026 |
| Study types include | 754 reviews, 274 randomised controlled trials, 171 systematic reviews, 159 meta-analyses |
| Chunks | 21,210 (500 characters, 100 overlap) |
| Quality check | 98.5% mention diabetes in the title or abstract; 0 duplicate PMIDs |

## ⚙️ Prerequisites

- Python 3.11+
- [Ollama](https://ollama.com/) installed and running, with Llama 3 downloaded:

```bash
ollama pull llama3
```

The embedding model (`all-MiniLM-L6-v2`) downloads automatically the first time it is used.

## 🚀 Setup & Installation

### 1. Clone the repository

```bash
git clone https://github.com/VishalSaravanan02/diabetes-rag-llm.git
cd diabetes-rag-llm
```

### 2. Create and activate a virtual environment

```bash
python3.11 -m venv .venv
source .venv/bin/activate        # macOS/Linux
.venv\Scripts\activate           # Windows
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Add your NCBI details

NCBI asks for a real email address when you download from PubMed. Copy the template and fill it in:

```bash
cp .env.example .env
```

Then edit `.env`. `ENTREZ_EMAIL` is required. `NCBI_API_KEY` is optional but makes fetching faster (free, from your [NCBI account settings](https://www.ncbi.nlm.nih.gov/account/)). `.env` is git-ignored, so your details are never committed.

## 🔧 Building the Knowledge Base

Run these once, always from the **project root** using `python -m`:

### Step 1: Fetch PubMed abstracts (a few minutes)

```bash
python -m src.fetch_data --from-year 2010 --to-year 2026 --per-year 300
```

Saves `data/diabetes_abstracts.json` and a record of how it was fetched (`diabetes_abstracts.meta.json`). An existing corpus is never overwritten unless you add `--overwrite`.

Optional quality report (year distribution, study types, duplicates, random sample of titles):

```bash
python -m scripts.check_corpus --sample 15
```

### Step 2: Chunk the abstracts

```bash
python -m src.preprocess
```

Splits abstracts into 500-character chunks with 100-character overlap (or sentence-aware chunks, see `CHUNK_STRATEGY`). Each chunk keeps its paper's PMID, title, authors, journal, year and study types.

### Step 3: Build the search index (about a minute on an Apple M-series laptop)

```bash
python -m src.embeddings
```

Also writes `index_meta.json`, which records the embedding model and a fingerprint of the chunks. If you later change the model or re-chunk without rebuilding, the app stops with a clear message instead of silently searching an out-of-date index.

## 💬 Running the Application

### Option A: Streamlit web app (recommended)

```bash
streamlit run app.py
```

Then open [http://localhost:8501](http://localhost:8501).

- Ask a question and get an answer that cites PMIDs
- Each source card shows the title, authors, journal, year, similarity score, the excerpt used and a **View on PubMed** link
- Adjust how many sources are retrieved in the sidebar, which also shows facts about the knowledge base
- Off-topic questions get a clear "no relevant papers" message; if Ollama isn't running you're told how to start it

### Option B: Terminal

```bash
python main.py "Do SGLT2 inhibitors reduce heart failure hospitalisation?"   # one question
python main.py                                                              # interactive
```

### Quick search test (no LLM needed)

```bash
python -m src.retriever "What is HbA1c?"
```

Shows the top matches with their similarity scores.

## 📊 Evaluation

The evaluation is being rebuilt. The earlier RAGAS results were measured on a 50-abstract corpus that no longer exists, and they used the same model to write and to judge answers, so they are no longer reported here.

The new evaluation will measure **retrieval** (does the right paper appear in the top results?) separately from **answer quality** (faithfulness, relevance, citation accuracy), on a reviewed test set with a separate judge model, and report a before/after table for each improvement. See the roadmap below.

The legacy script still runs with `python -m src.evaluate`. It needs the `BAAI/bge-large-en-v1.5` embedding model, downloaded once with `huggingface-cli download BAAI/bge-large-en-v1.5`.

## ⚙️ Configuration

All settings live in `config.py`:

| Setting | Default | Description |
|---|---|---|
| `EMBEDDING_MODEL` | `"all-MiniLM-L6-v2"` | Sentence-transformers model used for the index and queries |
| `EMBED_WITH_TITLE` | `False` | Embed "title + chunk" instead of the chunk alone |
| `LLM_MODEL` | `"llama3"` | Ollama model used to write answers |
| `LLM_TEMPERATURE` | `0.0` | 0 = the same question always gets the same answer |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `500` / `100` | Chunk length and overlap, in characters |
| `CHUNK_STRATEGY` | `"recursive"` | `"recursive"` (character-based) or `"sentence"` (never splits a sentence) |
| `MIN_ABSTRACT_LENGTH` | `200` | Abstracts shorter than this are skipped |
| `TOP_K` | `5` | Default number of sources per question |
| `MIN_SIMILARITY` | `0.47` | Cosine similarity a source needs to count as relevant |

`MIN_SIMILARITY` was chosen with `python -m scripts.calibrate_threshold`: on 20 on-topic and 10 off-topic questions, on-topic questions scored 0.65–0.84 and off-topic ones 0.20–0.30, and 0.47 is the middle of the gap. Re-run the script after changing the embedding model.

> After changing `EMBEDDING_MODEL`, `EMBED_WITH_TITLE` or any chunking setting, rebuild with `python -m src.preprocess && python -m src.embeddings`.

## 🩺 Troubleshooting

**`CERTIFICATE_VERIFY_FAILED` when fetching from PubMed**
Python doesn't trust the secure certificate it received. On macOS with Python from python.org, run **Install Certificates.command** (in Applications > Python 3.x) once, or create the virtual environment with Homebrew's Python (`/opt/homebrew/bin/python3.11 -m venv .venv`). On a work or university network, a VPN, or with antivirus "web protection", HTTPS traffic may be intercepted: try another network.

**"Can't reach Ollama"**
Start Ollama with `ollama serve` (keep that terminal open), or open the Ollama app. With Homebrew, `brew services start ollama` keeps it running in the background.

**"Ollama doesn't have the model"**
Download it with `ollama pull llama3` (or whichever model `LLM_MODEL` names).

**"The search index is out of date"**
A setting or the chunks changed since the index was built. Rebuild with `python -m src.preprocess && python -m src.embeddings`.

**"No sufficiently relevant papers were found"**
Nothing in the knowledge base passed the relevance threshold. Try rephrasing with more specific terms. This is also the expected result for questions outside diabetes research.

**The fetch finished with "this corpus is INCOMPLETE"**
Some batches failed even after retries (usually an unstable connection). Re-run the same command with `--overwrite`.

## ⚠️ Known Limitations

- **Abstracts only**, not full papers, so answers can miss details found only in the full text
- **Search quality varies**: basic definitional questions (e.g. "What is HbA1c?") sometimes rank loosely related papers first
- **Citation format is inconsistent** with Llama 3 (8B): it doesn't always cite PMIDs in the requested form
- **Several excerpts from the same paper** can take up more than one source slot
- The corpus is a **snapshot** (fetched September 2026) and covers English-language papers only

Details and planned fixes are in [`docs/OBSERVATIONS.md`](docs/OBSERVATIONS.md).
